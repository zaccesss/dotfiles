# Reference

What every section of the config does and why it is set that way.

## `[user]`

```ini
name = Your Name
email = you@example.com
signingkey = ~/.ssh/id_ed25519_signing.pub
```

Use the same commit email on every machine so history stays attributed consistently. `signingkey` points at a dedicated SSH key used only for commit and tag signing, separate from the key used for authenticating to GitHub over SSH, so a compromised auth key can't also forge a signature.

## `[gpg]`, `[commit]`, `[tag]`, `[gpg "ssh"]`

```ini
[gpg]
format = ssh
[commit]
gpgsign = true
[tag]
gpgsign = true
[gpg "ssh"]
allowedSignersFile = ~/.ssh/allowed_signers
```

`gpg.format = ssh` tells Git to verify and produce signatures using SSH keys rather than GPG, no separate GPG keyring to manage. `allowedSignersFile` is Git's own local trust list, a plain text file mapping an email to a public key, used when Git verifies a signature locally (`git log --show-signature`). It has nothing to do with GitHub's own "Verified" badge, that's a separate check GitHub runs server-side against the public keys uploaded to the account.

## `[fetch]`, `[pull]`

```ini
[fetch]
prune = true
[pull]
ff = only
```

`fetch.prune` removes the remote-tracking copy of a branch once the branch is deleted on the remote, so a merged PR's branch stops showing after the next fetch or pull. `pull.ff = only` makes `git pull` move the branch forward only when that needs no merge. When local and remote have both changed, the pull stops with an error instead of writing a merge commit. The branch is then rebased or reset on purpose.

## `[core]`

```ini
hooksPath = ~/.git-hooks
```

Points at a global hooks directory such as the one installed from [git-hooks](../../git-hooks), a global setting so every repo on the machine runs them without per-repo setup. Remove this line if you don't run an equivalent hooks setup.

`windows/gitconfig` also sets:

```ini
sshCommand = C:/Windows/System32/OpenSSH/ssh.exe
```

Git for Windows ships its own `ssh.exe`, which cannot see keys loaded into the Windows OpenSSH agent (the `ssh-agent` service). Without this line, `ssh -T git@github.com` succeeds while `git clone` over SSH fails with `Permission denied (publickey)`. Pointing Git at the Windows client makes both use the same agent.

## `[credential]`

```ini
[credential]
helper = osxkeychain
[credential "https://github.com"]
helper =
helper = !gh auth git-credential
[credential "https://gist.github.com"]
helper =
helper = !gh auth git-credential
```

The bare `helper = osxkeychain` (or `libsecret`/`manager`) is the fallback for any HTTPS remote not covered by the two overrides below it. The empty `helper =` line on the `github.com` and `gist.github.com` blocks clears the inherited default before the `!gh auth git-credential` line adds the real one, without the empty line first, Git would try both helpers in sequence. This routes GitHub authentication through the GitHub CLI's own token rather than a separately stored password or personal access token.

## `[filter "lfs"]`

```ini
clean = git-lfs clean -- %f
smudge = git-lfs smudge -- %f
process = git-lfs filter-process
required = true
```

Standard Git LFS wiring, generated by `git lfs install` normally, checked in here so it doesn't need reinstalling by hand. Unrelated to identity or signing.

## `[init]`

```ini
defaultBranch = main
```

Every new repository starts on `main`, instead of `master`.
