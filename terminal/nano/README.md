# nano themes

GNU nano in the ten Zacess themes, so the editor matches the terminal around it.

## What is here

| Path | What it is |
| --- | --- |
| `themes/zacess-<theme>.nanorc` | One colour fragment per Zacess theme, generated by `terminal/terminal/scripts/build-themes.py` from `palette/zacess.json`. Not a file nano reads on its own: `zt` copies its lines into the rc file it writes. Do not edit by hand. |

## How a theme is chosen

nano accepts its interface colours only in its main rc file (a `set` in an included file is an
error), so `zt` writes that file on every switch: `~/.config/nano/nanorc` on macOS, Linux and WSL,
`%USERPROFILE%\.nanorc` on Windows. The file is the shared base from
[`editors/nano`](../../editors/nano/), then the chosen theme's lines from its fragment here, then
one `include` line for the syntax folder this machine's nano ships. Its first line names the theme
(`## zacess theme: <id>`), which `zt current` reads back. `zt doctor` reports drift when the
file differs from what `zt` would write now. nano reads its files at start, so an open nano keeps
its colours until it is reopened.

## Colours

Each file sets nano's interface colours (title bar, status line, prompts, key tags, line numbers,
selected text, search matches, the error bar and the scrollbar) in nano's three-digit hex form. nano
shows the nearest colour in the terminal's colour cube, so the generator measures every pair as
shown and holds text to 4.5:1 or more. Syntax highlighting uses nano's own definitions, which name
the terminal's colours and so follow the palette.

The settings, keys, install steps and accessibility notes are in
[`editors/nano`](../../editors/nano/).
